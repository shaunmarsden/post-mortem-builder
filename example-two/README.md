# Worked Example Two: A Blended Reason

The first [example](../example/) tests four cases, each with one identifiable dominant factor. This one tests something harder: a stated reason that genuinely blends three factors together with no clear primary one.

- [case.md](case.md): a rejection message naming a vague reason, a concrete schedule conflict, and a fit-with-the-group concern, all at once
- [output.md](output.md): the post-mortem, which refuses to collapse this into one tidy classification
- [review.md](review.md): whether the concrete factor got separated from the vaguer ones, rather than one being picked to make the whole thing look resolved
